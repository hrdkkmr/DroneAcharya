## Scope
Browser-first, local-first synthetic-training prototype. Target cycle: **configure → brief → observe → assess → report → evaluate → replay → adapt → repeat**, with actual individual/unit progress. No backend/network API is needed. No weapons, operational acquisition, interception guidance or real sensor fidelity claims. Coordinates, returns, identities and training cues are fictional. VR is explicitly an optional future extension, not a core dependency.

## Users and screens / current boundary
- **Home:** manual entry/presets, actual saved/unsaved reports/counts and descriptive saved comparable-score mean. The saved-history rules-1 planner prepares an explicit next briefing without auto-start.
- **Scenario Lab:** implemented validated presets/custom seed, environment, lighting/weather, reliability/noise/delay, independent/crossing/grouped pattern, count/duration/difficulty and instructor objectives/weights. No hidden answers in instructor config.
- **Console:** implemented authoritative delivered observation feed/capture-age/arrival/delay/provenance, uncertainty, selection, clock/health, stateful track/assessment/report/request, pause/reset/early exit.
- **AAR:** implemented one deterministic result/components/penalties, stored rubric/per-track audit, actual-log exact-prefix replay/evidence links, post-exercise expected/recorded outcomes, actual JSON/HTML/print. The same active profile can review a freshly derived sourced next exercise; a different-profile report does not transfer estimates.
- **Individual progress:** implemented actual saved eligible trends/data table, component means, latency n/missing, difficulty samples and raw comparisons; separate heuristic matching-context competencies with sample/range/source evidence and null empty values.
- **Unit performance:** implemented local anonymous group/profile aggregates with attempt-based weighting, denominators and sparse-data caveats, not multi-device/authenticated management.
- **Instructor desk:** implemented anonymous profiles/groups, comparisons, actual JSON/CSV backup, validated preview/confirmed atomic import, raw diagnostic recovery and confirmed local-history reset. Not an authenticated role or arbitrary decision-tree editor.

## Full target acceptance criteria
1. Navigation/required implemented controls execute real actions; no fabricated history/telemetry. Later targets must be explicitly labelled unavailable, not disguised with decorative actions.
2. Same generator/sensor versions + validated config/seed yield identical definitions; different seeds vary paths/timing.
3. Simulation time is independent of wall-clock pauses/accelerated pacing. Observations arrive on actual logged delivery times.
4. Worker owns truth/rubric; active views do not receive answer keys. Current/prior evaluator views and private-data operations unlock only after termination/reset. Offline client-side isolation is not security against source/devtools inspection.
5. Actions respect state/decision rules. Requests schedule additional attempts, not guaranteed returns.
6. One deterministic bounded evaluation derives from recorded delivered evidence/actions/declared rules/synthetic truth. Undelivered evidence creates no impossible task/penalty.
7. Replay folds actual recorded events, never regenerated trajectories/decisions. Cursor distinguishes time and exact applied order; read-only controls/links cannot change the score. Active replay/answer locks apply to current and prior reports.
8. Actual completed/aborted reviews persist in IndexedDB with transaction acknowledgements. Failures are visible, keep the actual in-memory report and offer retry/backup; completed records survive reload. Imports are strictly versioned/bounded/atomic; invalid entries are quarantined untouched, not silently repaired. Confirmed history reset is separate from console discard and rejects stale resurrection.
9. History uses actual saved/completed/comparable evidence; aborted/no-evidence/unsaved reports remain reviewable but excluded from performance/competency inference. Show denominators, missingness, sparse/configuration caveats and no invented zero history. **Verified for descriptive history and separate rules-1 heuristic estimates in the tested local scope.**
10. Explainable rules-based adaptation uses actual completed persisted history, holds for sparse/inconsistent evidence, avoids exact repeats and single-noisy-result difficulty increases. **Implemented/verified rules-1; fixed teaching thresholds, not ML or efficacy evidence.**
11. Strict build, unit/integration/component and production-browser critical flows pass before their gate is accepted; report actual outcomes and limits.

Statuses/evidence for every target and criteria1–11: [traceability](REQUIREMENTS_TRACEABILITY.md). The Phase6 gate covers the local criteria including10; it does not infer official compliance or universal production/browser/accessibility certification.

## Constraints
Desktop/laptop primary; small-screen navigation remains usable. No paid/external AI/specialized hardware dependencies. No authentication/trusted instructor or signed record claims. No external runtime fonts/assets/services. One active exercise per tab; active profile/config/private actions lock. Warn before leaving/reloading unfinished or pending work, without promising browser prompts or recovery. No active-run crash/reload recovery; no fabricated interrupted result. Export is manual portable backup, not cloud storage; IndexedDB is origin/browser-local and evictable. Only synthetic/anonymous data belongs here.
